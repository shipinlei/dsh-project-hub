# dsh-project-hub 接口约定（宿主 ↔ 客户端）

本文件是 `lib/index.js`（host）与 `client/client.js`（client）之间的**唯一契约**。两侧实现都必须严格遵守；改动必须先改本文件。

## 0. 通用

- 插件包名 / loader id：`dsh-project-hub`
- HTTP 路由前缀：`/dsh-project-hub/api/`
- 所有响应都是 JSON，且 `content-type: application/json; charset=utf-8`。
- 失败响应：HTTP 400/404/500/501 + `{ "ok": false, "error": "<人类可读中文原因>" }`。
- 客户端同源请求：`fetch(new URL(path.replace(/^\/+/, ''), document.baseURI).pathname + url.search, { cache: 'no-store' })`（模块由 `dsh-app://` 或 http 同源加载，不额外设 header；**必须保留 query**）。
- Host 侧鉴权：业务 handler 先在 `wrapRoute` 里调 `ctx.connection.requestRejection(req)`（可空安全）；返回数字状态码即 `res.writeHead(code); res.end()` 并 return，否则继续。
  - **桌面宿主例外**：`profileContext.name === 'desktop'` 时整段跳过该网关（与官方 dshmarket 的 `enforceHostGate = config.desktopHost !== true` 等价）——桌面页面经 `dsh-app://` 转发，未必携带浏览器会话凭证，不跳过会导致面板全部 401。跳过的请求会以 `auth-bypassed` 记入 `client-events.ndjson`；非桌面 profile 仍严格 401（记 `auth-rejected`）。
  - 桌面宿主只监听 `127.0.0.1`，安全边界不变；`/health` 仍要求回环，`/client-report` 在桌面宿主上放宽到「宿主转发的内进程请求」。

## 1. `GET /dsh-project-hub/api/state`

读取项目元数据、记忆作用域状态。

响应：
```json
{
  "ok": true,
  "version": 1,
  "profileDir": "C:\\Users\\<you>\\.dsh\\profiles\\desktop",
  "projects": {
    "<workspaceId>": {
      "description": "",
      "agentPreset": null,
      "provider": null,
      "model": null,
      "reasoningEffort": null,
      "updatedAt": "2026-11-10T07:00:00.000Z"
    }
  },
  "memory": {
    "available": true,
    "namespace": "mnemon",
    "storageScope": "global",
    "runtimeUserScope": "storage",
    "projectScoped": false,
    "error": null
  }
}
```
- `projects` 没有记录的 workspace 返回空对象（客户端要能处理缺键）。
- `memory.available=false` 表示读不到 settings 服务；`memory.error` 放原因。
- `projectScoped = storageScope === 'workspaces' || storageScope === 'workspace'`。

## 2. `POST /dsh-project-hub/api/project`

写单个项目的元数据（浅合并）。

请求体：
```json
{ "workspaceId": "5fe363cc-...", "patch": { "description": "订单对账系统", "agentPreset": "standard", "provider": "deepseek-official", "model": "deepseek-flash", "reasoningEffort": "high" } }
```
- `patch` 只允许白名单键：`description` `agentPreset` `provider` `model` `reasoningEffort`。
- 值为 `null` 或 `""` 表示清除该字段。
- 未知键忽略（不报错）。
- `workspaceId` 缺失或非字符串 → 400。

响应：`{ "ok": true, "workspaceId": "...", "project": { ...合并后的完整对象 } }`

## 3. `GET /dsh-project-hub/api/rules?workspaceId=<id>`

项目规则（AGENTS.md 系）预览。按官方发现规则给出候选链，存在才读内容片段：

链条顺序（宽 → 专）：
1. `$DSH_HOME/AGENTS.md`
2. `$DSH_AGENTS_HOME/AGENTS.md`（若设置），否则 `~/.agents/AGENTS.md`
3. 项目根（从 workspace.path 向上找第一个含 `.git` 的目录；找不到就用 workspace.path）下的 `AGENTS.md`、`CLAUDE.md`
4. 同上目录的 `AGENTS.local.md`、`CLAUDE.local.md`

响应：
```json
{
  "ok": true,
  "projectRoot": "D:\\dev\\dsh-project-hub",
  "files": [
    { "path": "C:\\Users\\<you>\\.dsh\\AGENTS.md", "scope": "global", "exists": false, "size": 0, "excerpt": null },
    { "path": "C:\\Users\\<you>\\.agents\\AGENTS.md", "scope": "agents", "exists": false, "size": 0, "excerpt": null },
    { "path": "D:\\projects\\...\\AGENTS.md", "scope": "project", "exists": true, "size": 812, "excerpt": "前 4000 字符" },
    { "path": "D:\\projects\\...\\AGENTS.local.md", "scope": "project-local", "exists": false, "size": 0, "excerpt": null }
  ]
}
```
- `excerpt` 最多 4000 字符，超出截断；
- `scope` 取值：`global`（DSH_HOME）/ `agents`（~/.agents 或 $DSH_AGENTS_HOME）/ `project`（项目根 AGENTS.md、CLAUDE.md）/ `project-local`（同名 `.local.md` 叠加）；客户端负责映射成中文标签；
- `workspaceId` 缺失或非法 → 400；未知 workspaceId → 404。

## 4. `POST /dsh-project-hub/api/memory-scope`

切换 Mnemon 记忆作用域（设置 `mnemon` 命名空间的 `storageScope` / `runtimeUserScope`）。

请求体：
```json
{ "storageScope": "workspaces", "runtimeUserScope": "global" }
```
- `storageScope` ∈ `"global" | "workspaces" | "workspace"`；`runtimeUserScope` ∈ `"storage" | "global"`，可省略（省略则不动）。
- 实现方式（host）：读 `ctx.settings.describe({ redactSecrets: true })` 拿到 `ns === 'mnemon'` 的 `revision` 与当前值，再 `ctx.settings.mutate('mnemon', [{ op: 'set', path: ['storageScope'], value }], revision)`（`runtimeUserScope` 同法，可合并成一个 mutate 调用）。
- 服务不可用 → 501 `{ ok:false, error:"当前 profile 未提供设置服务，无法切换记忆作用域" }`。

响应：`{ "ok": true, "memory": { ...同 state.memory... } }`

## 5. `POST /dsh-project-hub/api/client-report`

客户端渲染器上报事件（安装/验收诊断用）。**免宿主鉴权**：本机回环请求直接接受；桌面宿主上放宽到「宿主转发的内进程请求」（可能没有 `req.socket`）。只写 `<stateDir>/client-events.ndjson`，不入会话数据。

请求体：
```json
{ "event": "mounted", "data": { "panelId": "dsh-project-hub", "services": { "sessions": true, "uiWorkspace": true, "layout": true, "modelSelection": true } } }
```
- `event` ∈ `"mounted"`（插件 apply 成功注册面板与侧栏入口）| `"panel-view"`（面板首次成功渲染并拉到 `/state`）。
- `data` 可选，任意 JSON，序列化后超过 2000 字符会记为 `"data-too-large"`。
- 日志最多保留 200 行，超出时截断为最近一半；宿主侧还会写 `auth-bypassed` / `auth-rejected` 两类诊断事件。

响应：`{ "ok": true, "event": "mounted" }`；非法 event → 400。

用途：页面刷新或打开面板后，宿主侧可用 `/health.clientEvents` 确认“渲染器确实加载了插件、面板确实渲染成功”，无需依赖人工描述。

## 6. `GET /dsh-project-hub/api/health`（诊断，免宿主鉴权，仅回环）

排障用只读接口：**不经过 `connection.requestRejection`**，但只接受回环地址（`127.0.0.1` / `::1` / `::ffff:127.0.0.1`），非回环返回 403。不返回任何文件内容。

响应：
```json
{
  "ok": true,
  "plugin": "dsh-project-hub",
  "profileDir": "C:\\Users\\<you>\\.dsh\\profiles\\desktop",
  "profileSource": "profileContext",
  "profileName": "desktop",
  "desktopHost": true,
  "loadedAt": "2026-11-11T01:34:08.049Z",
  "statePath": "C:\\...\\.dsh-project-hub\\state.json",
  "projectCount": 0,
  "client": {
    "registered": true,
    "file": "D:\\dev\\dsh-project-hub\\client\\client.js",
    "rev": "366c91fcd168"
  },
  "clientEvents": { "count": 0, "last": null },
  "memory": { "available": true, "namespace": "mnemon", "storageScope": "workspaces", "runtimeUserScope": "global", "projectScoped": true, "error": null }
}
```
- `client.registered` = 客户端 bundle 是否已被 `client-modules` 收录（决定侧栏入口会不会出现）；`rev` 用于构造实际下发地址：`/plugins/??dsh-project-hub/client.js&rev=<rev>`。
- `clientEvents.last` = 最近一条客户端上报（含 `at` / `event` / `data`），用于确认渲染器已加载面板。
- 该路由是安装/验收/排障通道，业务数据仍走第 1–5 节的鉴权路由。

## 7. 客户端可用的其它能力（不走 HTTP）

- 数据读取：slot 组件 props 里由宿主注入的 `useSessions` / `useWorkspaces` / `usePanelInfo` 选择器钩子。
  - `useSessions(s => s.byId[sessionId])` → 会话行：`{ id, displayTitle, title?, cwd?, running, blank, updatedAt, parentId?, origin? }`
  - `useWorkspaces(s => s.items)` → 工作区：`{ workspaceId, path, title, sessionIds, createdAt, updatedAt }`
- 新建会话（`apply` 里拿服务，通过 slot `inject` 传进组件）：
  ```js
  const sessionId = await sessions.create({ workspaceId, ...(agentPreset ? { agentPreset } : {}) });
  if (provider && model) {
    // 客户端模型选择**不是** ctx.sessions.selectModel，而是 Remote 命名空间：
    const result = await ctx.remote.session.selectModel({ sessionId, provider, model, ...(reasoningEffort ? { reasoningEffort } : {}) });
    if (result && result.ok === false) throw new Error(result.error?.code + ': ' + result.error?.message);
  }
  uiWorkspace.openSession(sessionId);
  ```
  - `sessions` = `ctx.sessions`（ClientSessions，只有 create/fork/list 等，**没有** selectModel）；
  - `uiWorkspace` = `ctx.get('uiWorkspace')`；`ctx.remote` = `dsh-api-gateway` 的 ClientRemote（官方 `ui-model-selection` 即用 `ctx.remote.session.selectModel`，见其 client.js:1037/880）。
  - 必须容错：任一服务缺失时给出可读错误，不崩溃；`selectModel` 失败时提示「会话已创建」但不要打开新会话。
- 打开已有会话：`uiWorkspace.openSession(sessionId)`。
- URL 拼装：同源请求必须保留 query，`new URL(rel, document.baseURI)` 后返回 `pathname + search`（丢掉 search 会让 `/rules?workspaceId=` 失效）。

## 8. 状态文件

`<profileDir>/.dsh-project-hub/state.json`
```json
{ "version": 1, "projects": { "<workspaceId>": { "description": "", "agentPreset": null, "provider": null, "model": null, "reasoningEffort": null, "updatedAt": "ISO" } } }
```
- 原子写：写 `state.json.tmp` 后 `renameSync`。
- 读失败（文件不存在/JSON 损坏）→ 返回空状态，不抛错；损坏时把原文件重命名为 `state.json.corrupt-<时间戳>` 并记 console.warn。
