### 7.2 客户端「侧栏不出现」的根因与修复（2026-11-11）

用户反馈刷新后仍看不到侧栏入口。加入诊断信标（`POST /client-report` + `GET /beacon` 双通道，记录 factory-start / apply-start / locale / services / slot 各阶段）后，从 `client-events.ndjson` 直接读到真实运行页面（`dsh-app://app/`）的执行序列，定位根因链：

1. **首次 apply 在注册完槽位后抛出 `cannot get property "remote.session" without inject`** —— 代码里 `servicesReady()` 通过 `ctx.get('remote')` 拿到的不是可用服务，访问 `.session` 被 cordis 的 inject 守卫拒绝；抛出后整次激活失败、已注册的槽位被回滚，于是**侧栏入口根本不存在**（这正是“刷新也看不到”的原因）。
2. 首次失败时 locale 注册未清理，后续 HMR 重载便报 `locale namespace "dsh-project-hub" already has locale "zh"`，把真正的首错掩盖掉。

修复（`client/client.js`）：
- `remote` 改为 `ctx.inject(["sessions","uiWorkspace","remote"], …)` 注入后再用；`servicesReady()` 里所有服务探测加 try/catch；
- locale 注册幂等（重复注册容错）；槽位注册 `registerSafely` 容错；整个 apply 外层包裹，错误上报信标后抛出；
- 保留诊断信标作为排障通道。

修复后实测（真实桌面页面，`dsh-app://app/`）：`apply-start → locale-ok → services-ok {sessions:true, uiWorkspace:true, remote:true} → slots-wait → main-slot-ready → panellist-slot-ready → slots-registered → mounted {panelId, services}`，无 `apply-error`/`slots-error`。**验收 #1 的“入口注册成功”已由真实渲染器上报确认**，且热更新后无需再次刷新页面。

### 7.3 侧栏会话按项目分组（2026-11-11）

用户反馈侧栏会话「按时间展示」，要求改成按项目（工作区）分组、组内按时间排列。取证发现两处原因叠加：

1. 官方 `ui-workspace` 的视图状态存在 `localStorage["dsh.workspace.view.v5"]`，当时为 `{"groupBy":"flat","orderBy":"updated"}`（单列表）。这不是默认值——该 store 初值是 `groupBy:"workspace"`（`dsh-client-ui-workspace` 的 `createWorkspaceViewStore`）。
2. 用户装了 Claude 风格皮肤 `dsh-claude-style@0.19.10`：它的「日期视图」（`dateGroups`）先把原分组写进 `localStorage["dsh-claude-group-before-date-view"]`，再 `setGroupBy("flat")` 强制单列表，并在 DOM 上画「今天/昨天/星期几」日期分段；皮肤每个页面加载都会重新打开日期视图（installer 无条件 `g()`），侧栏标题行右端有一枚铃铛（`aria-label="切换日期视图"`）在两种排法之间切换。这是「看起来按时间排」的直接来源。

方案：插件启动时把侧栏切回官方「按工作区」分组，组内仍是「最近更新时间」倒序（即项目内按时间排列）：

- 服务入口：`ctx.inject(["uiWorkspace"])` → `uiWorkspace.view.setGroupBy("workspace")`（官方 ui-workspace 把 view write set 挂在服务上，插件只调写口，不改核心）。
- 皮肤处理：若 `document.body` 带 `data-dsh-claude-date-groups`（日期视图激活），先 `document.dispatchEvent(new CustomEvent("dsh-claude-toggle-date-view"))` 让皮肤自己恢复分组、拆掉日期分段，再写 `setGroupBy("workspace")`；否则皮肤同步循环会立刻把 `groupBy` 改回 flat。
- 时序：皮肤可能在插件之后安装，故 apply 后按 `[0,300,800,1600,3000,5000,8000]ms` 重试，命中即停；面板「侧栏会话排列」可点「不干预」关闭自动切换（偏好存 `localStorage["dsh-project-hub.sidebar-grouping.v1"]`，默认 on）。

实测（真实桌面页面，热更新后无需刷新）：

- 信标：`GET /dsh-project-hub/api/health` → `clientEvents.last` = `sidebar-grouping {source:"auto-initial", delay:0}`。
- `%APPDATA%\@deepseek-ai\dsh-desktop\Local Storage\leveldb\000004.log` 最新写入（偏移 26624，10:33:24）为 `{"groupBy":"workspace","orderBy":"updated",...}` —— 官方 store 已落盘为按工作区分组。
- 自检：`test-client-dom.mjs` 新增 4 项断言（启动关日期视图→`setGroupBy("workspace")`；状态条渲染；点「按项目分组」再次切；点「不干预」持久化 off），四套脚本全绿（host 21/21、client smoke、interaction、DOM 16/16）。
