# 项目工作台 dsh-project-hub — 设计结论

状态：设计已与用户确认（2026-11-10），进入实施。
原则：**不改核心、不劫持数据**。复用官方 workspace / Mnemon / AGENTS.md 能力，插件只补平台缺的那一块。

## 1. 目标

给 DSH Web GUI 增加一个「项目工作台」视图，让**项目（= 工作区目录）**成为组织会话、共享记忆与设定的单位，而不是按时间流。典型场景：一个项目里做完一个功能，另开会话做下一个功能，新会话自动继承该项目的规则、默认模型与记忆。

## 2. 验收标准（6 条，全部要可复现）

1. 侧栏出现「项目」入口，点击能打开项目工作台面板。
2. 工作台能列出当前真实存在的项目（工作区）及其下会话（当前机器上 4 个：default-workspace、订单对账系统3.0、开发团队工作流、项目组开发插件）。
3. 在项目页一键新建会话：新会话的 cwd = 该项目目录，且套用项目默认模型 / 推理强度 / preset。
4. 项目 A 的记忆不会出现在项目 B 的会话里（Mnemon 作用域按工作区隔离）。
5. 项目根 `AGENTS.md` 的内容在该项目下所有会话生效（官方机制）。
6. 项目描述 / 默认设置在重启 DSH 后保持（profile 侧持久化）。

## 4. 设计决策

| # | 决策 | 说明 / 理由 |
|---|---|---|
| D1 | **项目 ≡ 一个工作区目录（1:1）**，复用官方 workspace 实体 | 官方已有 path/title/会话归属/归档/置顶；不造第二套身份。升级到「一项目多目录」只需改归组键，不动数据 |
| D2 | **不替换**原生侧栏与会话列表；新增顶层面板（`main`）+ 侧栏入口（`sidebar.panellist`） | 替换属非官方 shadow 用法，升级必冲突；并存成本最低 |
| D3 | 记忆作用域：`storageScope = workspaces`（profile 侧按 workspaceId 分目录）；`USER.md` 保持 global | 满足「项目内共享、项目间隔离」，不污染用户仓库 |
| D4 | 旧全局记忆：**备份归档**到 `~/.mnemon/runtime/archived/`，各项目从空记忆开始 | 不复制成 4 份避免漂移；需要时手动搬 |
| D5 | 项目规则走官方 `AGENTS.md`；插件只做预览 + 一键生成模板 + 打开文件 | 官方已处理层级/预算/增量，不另造指令文件 |
| D6 | 项目默认设置（模型/推理/preset）**快照式**，只在插件内新建会话时生效 | 不拦截原生入口（避免与核心 RPC 打架）；权限模式不纳入项目级（安全） |
| D7 | 项目元数据键 = workspaceId，存 `<profile>\.dsh-project-hub\state.json`；字段：描述、默认模型、默认推理、默认 preset、是否启用项目记忆、规则文件路径提示 | 不引入 `.dsh/project.json`，不写用户仓库 |
| D8 | **不做**：项目颜色/图标、功能层实体、内置富文本编辑器、跨项目移动会话、对外发布 | 控制 MVP 面积 |
| D9 | 记忆写入：自动沉淀 + 显式命令（`/remember-project`），写入前查重、单会话限额、追加式并发 | 防污染 |
| D10 | 删除项目 = 取消 workspace 注册（官方语义），会话永不删、落回收件箱 | 与核心一致 |

## 5. 技术方案

### 5.1 包结构

```
dsh-project-hub/
  package.json          # dsh 字段：bundle.patch + client.inject/platform
  cordis.patch.yml      # bundle 层：把插件插入 loader
  lib/index.js          # host cordis 插件（纯 JS，零构建）
  client/client.js      # client bundle（手写 __ModuleLoader__ 单文件，零构建）
  README.md
  docs/
```

**零构建链**：host 与 client 都是纯 JS（client 用 `React.createElement` / `react/jsx-runtime` 的 `jsx`），不引入 tsdown/typescript。代价是手写产物，收益是离线可用、无版本闸。

### 5.2 host 插件（lib/index.js）

- 状态存储：`<profile>/.dsh-project-hub/state.json`，原子写（临时文件 + rename），按 workspaceId 建表。
- HTTP 路由（挂 `webServer`）：`GET /dsh-project-hub/api/state`、`POST /dsh-project-hub/api/project`（写项目元数据）、`GET /dsh-project-hub/api/rules?workspaceId=`（读 AGENTS.md 预览）。
- 命令：`/remember-project` → 把指定内容写入当前工作区记忆（走 Mnemon 工具或直接文件追加，实施时定）。
- 记忆状态：读取插件配置判断 `storageScope`，在接口里回报「项目记忆：开启/全局」。

### 5.3 client 插件（client/client.js）

- 注册 `main` 面板（key = `project-hub`）+ `sidebar.panellist` 入口（label「项目」）。
- 组件树：项目列表（卡片）→ 项目详情（会话时间倒序、规则/记忆只读预览、默认设置表单、新建会话按钮）。
- 数据：`useWorkspaces()` + `useSessions()`；写操作走 host HTTP 路由；打开会话 `ctx.uiWorkspace.openSession(id)`。
- 新建会话：`ctx.sessions.create({workspaceId, cwd, ...项目默认})`。

### 5.4 安装与加载

- 本地包以 `link:` 或路径形式加入 `C:\Users\Administrator\.dsh\profiles\desktop\package.json` 的 dependencies，并加入 `dsh.profile.bundles`。
- `pnpm install`（profile 内），bundle patch 生效。
- host 插件需宿主重启；client bundle 刷新页面即可（待验证）。
- **回滚**：从 bundles 移除 + 删除依赖 + pnpm install；插件目录可整体删除。mnemon 配置改动前先备份原文件。

## 6. 风险与待验证

| # | 风险 | 应对 |
|---|---|---|
| R1 | `main` 槽位组件 props / 面板切换 API 不确定 | 先做「能注册、能渲染」的最小面板，再补交互 |

| R3 | host 插件需重启宿主，会中断当前会话 | 先在 client-only 纯 UI 阶段验证热加载；host 部分最后装 |
| R4 | 改 mnemon `storageScope` 影响所有会话 | 备份配置；可一键回滚到 global |
| R5 | 手写 client bundle 的维护性 | 结构分区清晰、注释充分；必要时后续再引入 tsdown |
